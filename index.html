Why this exists

Product owners ask two questions before they will sign ACs.

1. What will this look like on-screen?

A generic wireframe is not enough. They need a Salesforce-shaped click-through — Lightning pages, Path, related lists, Action Launcher — so the walkthrough feels like the org they will ship.

2. Can we stay OOTB, or do we need LWC / Flow / OmniStudio?

That question is the cost shape. The agent decides declarative-first (RULE 7a) and labels every control with the component that will implement it.

Traditional generators force clarify → write story → argue ACs → maybe mockup. AFLS Architects run the opposite: plan + prototype first, stories when the PO signs the shape.

Story contract · hard blockers

A story a developer can start without a follow-up meeting.

Concrete LSC persona

Field Sales Representative, MSL, KAM, Event Organizer — never “user”. HCP/HCO/KOL are the subject of the work, not the login role.

Business-language GWT

Three explicit lines, one When. No Apex class names, IP steps, SOQL, or *__c inside Given/When/Then.

Pattern E on every write

If records are created or updated, every object and every field is enumerated. “Etc.” is a fail.

Technical Implementation

A concise table after the ACs naming components, change type, and a one-line note. Effort S / M / L / XL / XXL.

How architects prompt it

Say it in English. STEP 0 routes the rest.

Plan and prototype HCO parent-child hierarchy for KAMs — no stories yet.
Migrate this Veeva story to Salesforce LSC: “As a Field Rep, I need a Sample Inventory screen…”
Write an LSC user story for Concur visit-expense allocation to event attendees.
Fix LSC Story: defect INQ-123 in medical inquiry intake — current: …, expected: …

What happens next

  • Asks 5–16 clarifying questions (structured multiple choice) before generating
  • Verifies custom components via code-review-graph
  • Verifies standard LSC objects via salesforce-docs
  • Writes the artifact into requirements/
  • Offers QTA, diagrams, GUS, and “promote to stories?”

Install · Cursor

Drop the skill into a project. Reload. Prompt.

git clone https://github.com/dipankardixit-ai/afls-architects.git cp -R afls-architects/skills/lsc-delivery-architect your-project/.cursor/skills/ cp afls-architects/rules/use-lsc-delivery-architect.mdc your-project/.cursor/rules/

Reload the Cursor window. Then verify:

  • “Plan and prototype a test capability — no stories yet” → Plan + Prototype mode, Phase 1–2 questions only.
  • “Write an LSC user story for a test field” → 5–16 LSC clarifying questions.

Optional MCP: code-review-graph for custom components, salesforce-docs for standard LSC facts. Without them the skill still runs — unverifiable names are marked (proposed).
